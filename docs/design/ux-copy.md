# UX copy for RAGnarok

This guide helps contributors write short, consistent messages in the document research workspace. The current interface uses a direct tone; several reusable states are still being developed.

## Voice

Be clear, calm, and specific. Say what happened and what the user can do next.

## Buttons

Use short action labels such as “Upload”, “Ask”, and “Sign out”. Keep labels verb-first when possible.

## Empty states

Explain how to get started: “No documents yet. Upload a .txt or .md file to begin.” Do not leave an empty panel without context.

## Errors

Use plain language and preserve useful backend messages. Do not expose stack traces or provider keys.

## Confirmation

Confirm completed actions briefly, such as “Copied” or “Document deleted”. Keep the confirmation near the action when possible.

## Examples

“Thinking…” communicates pending chat work; “No documents yet.” gives the library a clear empty state. Use the slate and sky palette for visual hierarchy, not for conveying meaning by color alone.
